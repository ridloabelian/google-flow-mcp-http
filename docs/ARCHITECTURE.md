# Arsitektur & Implementasi MCP Server Google Flow (CDP + Streamable HTTP)

Dokumen ini merancang dan mengimplementasikan server **Model Context Protocol (MCP)** produksi untuk mengotomasi [Google Flow](https://flow.google.com/) menggunakan sesi browser Chrome asli melalui **Chrome DevTools Protocol (CDP)** dan mengeksposnya ke *remote AI agents* melalui transport **Streamable HTTP** (`POST`, `GET`, dan `DELETE /mcp`) berbasis [@modelcontextprotocol/sdk v1.30.0](https://agentcat.com/guides/building-mcp-server-typescript/).

## 1. Mengapa Arsitektur Hybrid CDP + Streamable HTTP Diperlukan

[Google Flow](https://flow.google.com/) tidak menyediakan REST API publik maupun API key resmi karena sistem pembayarannya terikat pada kuota kredit bulanan akun langganan konsumen Google AI ([Wireflow Guide](https://www.wireflow.ai/blog/google-flow-api)). Selain itu, terdapat tiga batasan teknis pada web app Flow yang menentukan desain server ini:

1. **Proteksi reCAPTCHA Enterprise pada Aksi Generasi**: Endpoint pembuatan video dan gambar menolak *raw HTTP request* yang tidak berasal dari interaksi UI asli di dalam tab browser terautentikasi ([RohaanA/google-flow-mcp](https://github.com/RohaanA/google-flow-mcp)). Sebaliknya, pembacaan daftar model dan riwayat melalui endpoint internal `/fx/api/trpc/...` (seperti `videoFx.getVideoModelConfig` dan `media.fetchUserHistoryDirectly`) dapat dieksekusi cepat dari dalam konteks tab yang sudah login ([Keysight Network Traffic Analysis](https://www.keysight.com/blogs/en/tech/nwvs/2025/08/04/google-flow-ai-har-analysis)).
2. **Deteksi `navigator.webdriver` saat Login Google**: Proses autentikasi akun Google menolak browser otomatis bawaan Playwright, sehingga Chrome asli harus diluncurkan di luar Playwright dengan `--remote-debugging-port=9222` dan profil persisten `--user-data-dir`, kemudian di-attach secara non-intrusif lewat `chromium.connectOverCDP()` ([ParkSangGwon/google-flow-mcp Architecture](https://github.com/ParkSangGwon/google-flow-mcp/blob/main/docs/architecture.md)).
3. **Kesenjangan Akses File untuk Remote Agent**: Server MCP berbasis `stdio` tradisional hanya mengembalikan *path* file lokal (misalnya `~/FlowExports/video.mp4`) yang tidak bisa diakses oleh agen di VPS atau cloud berbeda ([RohaanA/google-flow-mcp](https://github.com/RohaanA/google-flow-mcp)). Arsitektur ini menambahkan endpoint unduhan HTTPS bertanda tangan **HMAC-SHA256** (`/media/:filename?exp=...&sig=...`) agar agen jarak jauh dapat langsung mengunduh atau memproses klip MP4/PNG tanpa mengekspos direktori penyimpanan.

## 2. Topologi Sistem & Batas Keamanan Jaringan

Port debugging CDP (`9222`) memberikan kendali penuh atas profil browser tanpa autentikasi, sehingga **tidak boleh diekspos ke jaringan publik** ([ParkSangGwon/google-flow-mcp Architecture](https://github.com/ParkSangGwon/google-flow-mcp/blob/main/docs/architecture.md)). Seluruh lalu lintas eksternal dari agen remote wajib melewati reverse proxy TLS menuju Express Streamable HTTP Server (`3100`) yang dilindungi autentikasi Bearer Token sesuai [Spesifikasi Otorisasi MCP](https://modelcontextprotocol.io/docs/2025-11-25/tutorials/security/authorization) serta validasi header `Host` anti-DNS-rebinding ([MCP TypeScript SDK](https://github.com/mcp-auth/mcp-typescript-sdk)).

| Zona Jaringan | Komponen | Port & Binding | Mekanisme Proteksi & Referensi |
| :--- | :--- | :--- | :--- |
| **Publik / Tailnet** | Reverse Proxy (Caddy / Nginx / Cloudflare Tunnel) | `443/tcp` (HTTPS TLS 1.3) | Terminasi TLS, penonaktifan *response buffering* untuk SSE Streamable HTTP, dan timeout baca 600 detik ([AgentCat TypeScript Guide](https://agentcat.com/guides/building-mcp-server-typescript/)). |
| **Host Internal / Bridge** | `flow-mcp-server` (Express + MCP SDK) | `127.0.0.1:3100` | Verifikasi `Authorization: Bearer` dengan `crypto.timingSafeEqual` ([MCP Authorization Docs](https://modelcontextprotocol.io/docs/2025-11-25/tutorials/security/authorization)), allowlist header `Host` ([MCP TypeScript SDK](https://github.com/mcp-auth/mcp-typescript-sdk)), dan tanda tangan URL media HMAC-SHA256. |
| **Loopback / Isolated Bridge** | `chrome-flow` (Real Chrome / KasmVNC Chromium) | `127.0.0.1:9222` (CDP) & `127.0.0.1:3001` (GUI Login) | Ditolak otomatis oleh `CdpSessionManager` bila mengarah ke IP publik; profil login tersimpan lokal tanpa ekstraksi cookie ([TMSSS05/google-flow-browser-mcp](https://github.com/TMSSS05/google-flow-browser-mcp)). |

## 3. Alur Eksekusi End-to-End (Multi-Client Remote Agents ke Single Chrome Tab)

1. **Inisialisasi Sesi (`POST /mcp`)**: Agen remote mengirim request JSON-RPC `initialize` dengan header `Authorization: Bearer <TOKEN>`. Server memvalidasi token, membuat instance `StreamableHTTPServerTransport` dan `McpServer` khusus sesi tersebut, lalu mengembalikan header `Mcp-Session-Id` ([AgentCat TypeScript Guide](https://agentcat.com/guides/building-mcp-server-typescript/)). Server juga mendukung mode tanpa sesi (`FLOW_STATELESS_HTTP=true`) untuk klien spesifikasi 2026-07-28.
2. **Langganan Progres Real-Time (`GET /mcp`)**: Agen membuka aliran Server-Sent Events (SSE) menggunakan `Mcp-Session-Id` yang sama untuk menerima log progres (`notifications/message`) setiap 5 detik selama proses *rendering* Veo 3.1 berlangsung agar koneksi proxy tidak memutus request karena idle.
3. **Antrean Eksklusif & Guardrail Kredit (`FlowJobQueue`)**: Meski beberapa agen remote terhubung serentak, semua mutasi UI masuk ke *global single-job mutex* (`enqueueExclusive`). Sebelum menekan tombol *Generate*, controller membaca kuota kredit dari UI Flow (`Generating will use N credits`), membandingkannya terhadap `FLOW_MAX_CREDITS_PER_CALL` dan `FLOW_DAILY_CREDIT_CAP`, serta mendukung mode simulasi `dryRun: true` ([RohaanA/google-flow-mcp](https://github.com/RohaanA/google-flow-mcp)).
4. **Resolusi DNS-ke-IPv4 Otomatis untuk CDP Docker**: Chrome 113 ke atas menolak header `Host: chrome-flow:9222` dengan error HTTP 500 karena hanya menerima `localhost` atau alamat IP literal. `CdpSessionManager` otomatis me-resolve nama container `chrome-flow` menjadi IPv4 internal Docker (`172.x.x.x`) sebelum memanggil `/json/version` dan `connectOverCDP()`.
5. **Deteksi Tile Baru & Pengiriman URL Bertanda Tangan**: Hasil render muncul sebagai elemen `<flow-video-tile>` atau `<flow-image-tile>` dengan urutan terbaru di paling atas dan URL sementara `/asb/<token>` ([ParkSangGwon/google-flow-mcp Architecture](https://github.com/ParkSangGwon/google-flow-mcp/blob/main/docs/architecture.md)). Server mengunduh biner media menggunakan konteks cookie browser (`page.context().request.get`), menyimpannya berdasarkan hash SHA-256 (`flow_<8char>_<jobId>.mp4`), lalu mengembalikan URL HTTPS bertanda tangan HMAC-SHA256 ke agen remote.
