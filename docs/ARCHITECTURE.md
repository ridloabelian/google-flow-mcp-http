# Google Flow MCP Server Architecture (CDP + Streamable HTTP)

This document details the production architecture of `google-flow-mcp-http`, a **Model Context Protocol (MCP)** server that automates [Google Flow](https://flow.google.com/) using a real Chrome browser via **Chrome DevTools Protocol (CDP)** and exposes it to remote AI agents over **Streamable HTTP** (`POST`, `GET`, and `DELETE /mcp`) built on [@modelcontextprotocol/sdk v1.30.0](https://agentcat.com/guides/building-mcp-server-typescript/).

## 1. Why Hybrid CDP + Streamable HTTP Is Required

[Google Flow](https://flow.google.com/) does not offer a public REST API or developer API key because billing is tied to consumer Google AI subscription credits ([Wireflow Guide](https://www.wireflow.ai/blog/google-flow-api)). Three technical constraints dictate this architecture:

1. **reCAPTCHA Enterprise Protection on Generation**: Video and image generation endpoints reject raw HTTP requests that do not originate from genuine UI interactions inside an authenticated browser tab ([RohaanA/google-flow-mcp](https://github.com/RohaanA/google-flow-mcp)). Meanwhile, model configs and history can be read quickly via internal `/fx/api/trpc/...` endpoints (such as `videoFx.getVideoModelConfig` and `media.fetchUserHistoryDirectly`) from inside the authenticated tab ([Keysight Network Traffic Analysis](https://www.keysight.com/blogs/en/tech/nwvs/2025/08/04/google-flow-ai-har-analysis)).
2. **`navigator.webdriver` Detection on Google Sign-In**: Google authentication rejects Playwright-launched automated browsers. A real Chrome instance must be launched externally with `--remote-debugging-port=9222` and a persistent `--user-data-dir`, then attached non-intrusively via `chromium.connectOverCDP()` ([ParkSangGwon/google-flow-mcp Architecture](https://github.com/ParkSangGwon/google-flow-mcp/blob/main/docs/architecture.md)).
3. **Remote Agent File Access Gap**: Traditional `stdio` MCP servers return local file paths (such as `~/FlowExports/video.mp4`) that remote agents on other servers cannot read ([RohaanA/google-flow-mcp](https://github.com/RohaanA/google-flow-mcp)). This server adds an **HMAC-SHA256** signed HTTPS download endpoint (`/media/:filename?exp=...&sig=...`) so remote agents can fetch generated MP4/PNG assets directly without exposing the host filesystem.

## 2. Network Topology & Security Boundaries

CDP debugging port `9222` grants full unauthenticated control over the browser profile and **must never be exposed to the public internet** ([ParkSangGwon/google-flow-mcp Architecture](https://github.com/ParkSangGwon/google-flow-mcp/blob/main/docs/architecture.md)). All external traffic from remote agents must traverse a TLS reverse proxy into the Express Streamable HTTP Server (`3100`), protected by Bearer Token authentication ([MCP Authorization Docs](https://modelcontextprotocol.io/docs/2025-11-25/tutorials/security/authorization)) and DNS-rebinding `Host` header validation ([MCP TypeScript SDK](https://github.com/mcp-auth/mcp-typescript-sdk)).

| Network Zone | Component | Port & Binding | Security Controls & References |
| :--- | :--- | :--- | :--- |
| **Public / Tailnet** | Reverse Proxy (Caddy / Nginx / Cloudflare Tunnel) | `443/tcp` (HTTPS TLS 1.3) | TLS termination, disabled response buffering for Streamable HTTP SSE, and 600s read timeouts ([AgentCat TypeScript Guide](https://agentcat.com/guides/building-mcp-server-typescript/)). |
| **Host / Internal Bridge** | `flow-mcp-server` (Express + MCP SDK) | `127.0.0.1:3100` | Timing-safe `Authorization: Bearer` verification (`crypto.timingSafeEqual`) ([MCP Authorization Docs](https://modelcontextprotocol.io/docs/2025-11-25/tutorials/security/authorization)), `Host` allowlist ([MCP TypeScript SDK](https://github.com/mcp-auth/mcp-typescript-sdk)), and expiring HMAC-SHA256 media URLs. |
| **Loopback / Isolated Bridge** | `chrome-flow` (Real Chrome / KasmVNC Chromium) | `127.0.0.1:9222` (CDP) & `127.0.0.1:3001` (Login GUI) | `CdpSessionManager` blocks non-private CDP hosts by default; Google login cookies stay inside the browser profile without extraction ([TMSSS05/google-flow-browser-mcp](https://github.com/TMSSS05/google-flow-browser-mcp)). |

## 3. End-to-End Execution Flow (Multiple Remote Agents -> Single Chrome Tab)

1. **Session Initialization (`POST /mcp`)**: A remote agent sends a JSON-RPC `initialize` request with `Authorization: Bearer <TOKEN>`. The server validates the token, creates a per-session `StreamableHTTPServerTransport` and `McpServer`, and returns an `Mcp-Session-Id` header ([AgentCat TypeScript Guide](https://agentcat.com/guides/building-mcp-server-typescript/)). Stateless mode (`FLOW_STATELESS_HTTP=true`) is also supported for 2026-07-28 spec clients.
2. **Real-Time Progress Stream (`GET /mcp`)**: The agent opens an SSE stream using `Mcp-Session-Id` to receive `notifications/message` progress events every 5 seconds during Veo 3.1 rendering, keeping proxy connections active.
3. **Exclusive Queue & Credit Guardrails (`FlowJobQueue`)**: Even with concurrent remote agents connected, all UI mutations pass through a global single-job mutex (`enqueueExclusive`). Before clicking Generate, the controller reads the Flow UI credit quote (`Generating will use N credits`), enforces `FLOW_MAX_CREDITS_PER_CALL` and `FLOW_DAILY_CREDIT_CAP`, and supports `dryRun: true` ([RohaanA/google-flow-mcp](https://github.com/RohaanA/google-flow-mcp)).
4. **Automatic DNS-to-IPv4 Resolution for Docker CDP**: Chrome 113+ rejects `Host: chrome-flow:9222` with HTTP 500 because it only accepts `localhost` or literal IP addresses. `CdpSessionManager` resolves Docker container hostnames to internal IPv4 addresses (`172.x.x.x`) before calling `/json/version` and `connectOverCDP()`.
5. **New Tile Detection & Signed Media Delivery**: Flow renders outputs in newest-first `<flow-video-tile>` or `<flow-image-tile>` elements with `/asb/<token>` URLs ([ParkSangGwon/google-flow-mcp Architecture](https://github.com/ParkSangGwon/google-flow-mcp/blob/main/docs/architecture.md)). The server fetches media binaries using the browser context (`page.context().request.get`), stores them by SHA-256 digest (`flow_<8char>_<jobId>.mp4`) to prevent duplicates on resume, and returns an HMAC-SHA256 signed HTTPS URL.
